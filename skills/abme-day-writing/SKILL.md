# ABME 日更写作

当用户在做 ABME / 第二个我 的日更、定位、理论页或公众号草稿时使用。

目标：把「对齐 → 落库 → 成文 → 草稿」跑成可复用闭环，而不是一次写完硬塞。

## 硬闸门

1. **先讨论，后落库。** 没确认前不写思源长文、不重写定位准绳、不更新公众号草稿。
2. **默认中文。** 对用户可见的说明、确认句、配图提示一律中文；除非用户明确要求英文。
3. **草稿默认不发布。** 只有用户明确说「发布」才走发布。
4. **一句一确认。** 讨论时用用户的话收成短句，请他回「对/改」；不要自己发挥成大框架。
5. **混读知识库。** 写定位/为什么时，先读思源既有 ABME 文档与当日 memory，不空编。

## 默认产物落点

- 项目：`10-Projects / P2607-ABME 第二个我`
- 工作台：`<private-workspace>`
- 思源 API：`http://127.0.0.1:6806`
- 公众号草稿目录：`<private-drafts-directory>/`
- 日记忆：`memory/YYYY-MM-DD.md`
- 当前定位准绳：在私有知识库中维护；公开仓库仅保存可复用流程

## 主流程（7 步）

### 1. 先对齐范围和口径

先问今天只讲什么，不一上来写长文。

常见拆法：

- 它是谁
- 你的思路
- 为什么要这么做

不讲路径、工程清单、权限矩阵，除非用户明确要。

每一块只用用户的话收成一句，问：

> 对吗？要改哪几个字直接改。

用户回「对」再进下一块；用户改字，就按用户的字走。默认全程中文。

### 2. 需要时混读思源，不空编

不是只靠聊天记忆。写定位、为什么时，去读：

- 思源里 ABME 项目页 / 定位页
- 当日 memory
- 用户前面刚钉死的原话

目的：把旧准绳和新口径接上，不自己发明一套。

若用户说「上面不是说了吗」：立刻回查上下文 / memory / 思源，重述确认，不重开新题。

### 3. 确认后再写思源

只有关键句确认完，才落库。通常写：

- 当日口径 / 为什么页
- 若定位变了：重写定位准绳，并同步项目根页「1. 定位」
- 旧文保留，但标明「当前以哪篇为准」
- `memory/YYYY-MM-DD.md` 记：确认句、文档 id、下一步

没确认前，不改准绳，不批量灌文档。

### 4. 再写公众号正文给用户看

思源口径稳了，才写对外文章。

先在群里贴可读正文（去掉模板指令噪音），让用户审内容和语气。

这时还不急着排版、不急着塞很多样式。

### 5. 用户批准后才 CLI 进草稿

用户说「可以 / 批准」之后，才走：

`wxpub inspect` → `wxpub render` → `wxpub wechat draft create|update`

样式单独调：

- 去掉语义不对的 135（如峰会邀请函）
- 轻样式：小节标题 + 少量引用 / 收束
- 第一篇要有起势，不能像群聊续写

结果只进草稿箱，不发布。

本地草稿目录示例：`<private-drafts-directory>/abme-dayN-...`

### 6. 配图后置

正文定了再谈图。

- 默认 **1–2 张**：封面必须，正文最多再 1 张
- 先给**中文**出图提示
- 自动出图只有服务可用才试；不行就停，不硬生成
- 用户出好图后，写入 `assets/`，更新 front matter / 正文引用，再 draft update

### 7. 不自动发布

全程默认停在草稿。

只有用户明确说「发布」，才走发布。

发之前仍按清单核：

- 主题是否属于 ABME / 第二个我
- 有没有越界（尤其能源行业赛道）
- 标题与立场是否可公开

## 协作话术

- 确认句：`我先用你的话收成一句……对吗？要改哪几个字直接改。`
- 纠偏后：`收到，上一句偏了。按你刚说的重收：……`
- 落库后只报路径 / ID，不复读长文
- 群聊短句，少空行，不说明书腔

## 禁止

- 未确认就写最终理论页 / 改定位准绳 / 推草稿
- 把讨论扩成工程排期、权限矩阵、技能大重构
- 默认英文提示或英文对用户说明
- 自动发布公众号
- 倾倒私密笔记到群

## 验收

一次 ABME 写作闭环算完成，当且仅当：

1. 关键口径有用户确认记录
2. 思源有对应页与 id
3. 若需要对外：公众号草稿已更新且未擅自发布
4. memory 记下决策与路径
