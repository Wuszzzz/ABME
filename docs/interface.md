# ABME 工作台交互面

## 1. 总述

`abme` 不是单一命令行产品，而是本地调试工作台。

它面向两个交互面：

- 本地调试面：`abme`
- 前台运行面：飞书角色 agent

二者背后共用一个资源层：思源。

## 2. ABME 的核心交互

### 2.1 提示词调试

- 查看当前主 agent 和子 agent 的角色定义
- 对比旧版与新版提示词
- 记录修改原因、预期变化和实验结果

### 2.2 工作流联调

- 检查角色之间的调用关系是否合理
- 检查哪些动作应由 `J.A.R.V.I.S.` 统一调度，哪些应交给具体合伙人
- 检查飞书中实际协作是否与设计一致

### 2.3 运行复盘

- 汇总飞书层的异常、误判、冲突和有效案例
- 归因问题来源：规则、角色、知识、项目上下文还是执行方式
- 判断应回写到哪里

### 2.4 规则升级

- 稳定结论进入 `00-Core`
- 风格和偏好变更进入 `01-Profile`
- 长期方法进入 `20-Knowledge`
- 当前实验和调试过程进入 `11-Agent Debug`

## 3. 飞书层的核心交互

### 3.1 前台协作

- 用户直接与具体角色对话
- 多角色协作处理任务
- 形成实际反馈样本

### 3.2 运行反馈

- 记录角色失配
- 记录链路中断
- 记录有效工作流
- 记录需要 `abme` 继续调试的问题

## 4. 思源层的核心交互

### 4.1 默认读取

- `00-Core`
- `01-Profile`
- `10-Projects`
- `20-Knowledge`

### 4.2 默认写入

- 调试过程写入 `11-Agent Debug`
- 稳定规则写入 `00-Core`
- 长期知识写入 `20-Knowledge`
- 成品输出写入 `50-Outputs`

## 5. 当前最需要支持的动作

不是“做更多命令”，而是把下面这些动作做顺：

- 调试前读取上下文
- 调试后沉淀结果
- 飞书反馈回流
- 版本差异可追踪
- 结论升级路径清晰
