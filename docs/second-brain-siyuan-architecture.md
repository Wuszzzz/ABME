# 思源 Second Brain 架构

## 1. 定位

思源是整个 second brain 的资源层和知识真源。

它不是单纯的资料仓库，也不是只给某一个 agent 用的缓存层。

对于当前系统，思源同时服务于两个调用层：

- `abme` 调试工作台
- 飞书角色 agent 运行层

## 2. 当前笔记本结构

### 配置层

- `00-Core`
  - 程序性记忆
  - 放规则、角色、路由、方法、标签规范、双向链接规范
- `01-Profile`
  - 自我模型
  - 放目标、偏好、风格、决策标准、禁忌

说明：

- `00-Core` 和 `01-Profile` 是提示词配置源
- 生产环境会直接把稳定内容编译进提示词
- 运行时默认不全量读取，除非在维护规则本身

### 工作层

- `10-Projects`
  - 正在推进的项目、课题、调试工程、会议结论、问题单
- `20-Knowledge`
  - 长期结构化知识
- `30-Self Inbox`
  - 自己的原始输入
- `40-External Inbox`
  - 外部原始输入
- `50-Outputs`
  - 成品输出
- `90-Archive`
  - 历史归档

## 3. Agent 系统的最小读取规则

### `abme`

- 可读取全部核心区
- 重点读取：`00-Core`、`01-Profile`、`10-Projects`、`20-Knowledge`
- 用于提示词调试、工作流联调、复盘与规则升级

### 飞书角色 agent

- 默认读取：`00-Core`、`01-Profile`、`10-Projects`、`20-Knowledge`
- 尽量不把 `30-Self Inbox` 和 `40-External Inbox` 当作高置信上下文
- 读取结果以当前角色职责为准，不全量拉库

## 4. Agent 系统的最小写入规则

### 调试过程

- 默认写入 `11-Agent Debug`

### 稳定规则

- 写入 `00-Core`

### 稳定人格与偏好

- 写入 `01-Profile`

### 长期方法、经验、模式

- 写入 `20-Knowledge`

### 成品产出

- 写入 `50-Outputs`

## 5. Agent 调试工程

需要有一个独立笔记本承接 agent 系统的日常调试。

推荐结构：

```text
11-Agent Debug/
  README-Agent-调试工程-项目说明
  提示词调试记录
  工作流联调记录
  飞书角色运行复盘
  问题单与修复记录
```

用途说明：

- 这里放正在发生的调试，不放最终规则真源
- 它是调试承接层，不是长期知识终点
- 人格调教记录也优先进入这里，而不是直接改最终规则

## 6. 分流原则

### 进入 `10-Projects`

- 当前正在推进
- 有目标、状态、问题、下一步
- 包含调试工程、联调事项、运行问题

### 进入 `20-Knowledge`

- 已经抽象成长期方法
- 后续会被多个项目复用

### 进入 `30-Self Inbox`

- 自己的碎片想法
- 还没成项目，也还没成知识

### 进入 `40-External Inbox`

- 主要来自外部材料
- 尚未改写成自己的知识

### 进入 `50-Outputs`

- 已经是成品
- 但长期结论仍应回写到 `20-Knowledge`

## 7. 关键原则

1. 思源是系统资源方，不是聊天记录备份仓。
2. 飞书运行反馈必须能回流到思源。
3. `abme` 的调试结果必须先进入项目层，再决定是否升级。
4. `40-External Inbox` 不能变成纯收藏仓库。
5. `00-Core` 和 `01-Profile` 不用来堆临时调试记录。
